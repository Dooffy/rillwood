Apple TV - where the profile lives

Draft, not built. Where the current user's avatar goes on Apple TV and how the remote reaches Switch Account (Who's Watching), Settings and Sign Out from every tab. Drawn at 1920 × 1080 in the dark palette like apple-tv-screens.html; gradients stand in for art. Yellow dashes = a remote press that gets there, red = one that doesn't.

TodaySystem top tab bar: Home / Library / Search (NativeTabs, (tabs)/_layout.tsx). Avatar = round TvButton at the top right of Home only (TvHome), reached by Right from the hero's last button via a focus guide (TvHero rightDestination, apple-tv.md #12). Click → Who's Watching (TvAccounts); Settings = its gear; Sign Out = hold an account.
The problemOn a real Apple TV the user expects "who am I" in or by the top bar and reachable from every tab. Library, Search and detail pages have no way to Settings or Switch Account except Back to Home, then up into the hero.
Hard limitsThe system tab bar takes a title and / or an icon per item (SF Symbol, or an image - a remote picture would have to be saved to a file first, unverified) - no custom views inside it through react-native-screens. Its focus doesn't hand on to our views to its right (#12). It hides once focus moves into content.

Pros
  • Looks right: profile level with the tabs, like Apple's tab-bar apps
  • No new tab, the bar stays Home / Library / Search
  • Same menu everywhere (one component)
Cons
  • Not reachable from the tab bar itself - the place users look
  • Every tab needs its own guide; each new screen top must remember it
  • Hides / shows in step with the system bar: no API for that, we'd guess from scroll / focus
Effort - medium-high
  • New components/tv/TvProfileButton.tsx (avatar + menu)
  • TvHome (move it out), TvHero (guide target), TvLibrary, TvSearch (guides)
  • focus.tsx (a shared top-right guide)
  • TvAccounts (gear stays or goes), tests
Risks
  • tvOS focus engine: the tab bar is its own focus environment; Up from content may go to the bar, not our avatar - guide per screen (#11: guide destinations don't always hold)
  • Bar auto-hide: avatar left floating over content, or gone while the bar shows
  • Native variant (UIKit's tvOS-only tab bar accessory views via a react-native-screens patch): would sit in the bar, but unknown with the tvOS 18+ tab bar - spike first unverified

BA fourth tab: the user's icon, no name recommended

The system bar gets a fourth item at its right end - an icon only, no title (Home / Library / Search / ◯). VoiceOver reads the user's name. Its page = the account on the left (picture, name, server), Switch Account / Settings / Sign Out on the right.

Recommendation: B-icon - a fourth tab with a profile icon, no name

  • Only option that puts the profile in the bar and reaches it from every tab using the system's own focus - no new guides, and it removes the Home one (#12).
  • Tab: SF Symbol person (👤), no title (clean, fixed width, no name on screen); VoiceOver label = the user's name.
  • Page: avatar + name + server left; Switch Account (→ Who's Watching), Settings (→ TvSettings), Sign Out right. Who's Watching at launch stays. Remove the Home avatar in the same PR so there's one way in.
  • Spike B-avatar in the same task: the user's picture (or initials) saved to a file, set as the tab icon in its own colours, re-set on account switch. Works → swap it in; doesn't → the symbol stays, nothing blocked.
  • Also check: an icon-only tab sits and focuses like the others in the tvOS bar; mount cost when focus passes the tab.

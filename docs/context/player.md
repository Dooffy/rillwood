# Player (JS)

Read before working on `src/player/` (`PlayerEngine` interface, mpv adapter) or the player screen. Native side: `docs/context/mpv.md`. Device results + open issues: [`docs/test-plans/mpv.md`](../test-plans/mpv.md).

## PlayerEngine contract

Screens never import mpv directly.

```ts
export type Track = {
  id: number;
  lang?: string;
  title?: string;
  codec?: string;
  external?: string; // sidecar sub: the URI it was loaded from
};
export type PlayerProps = {
  source: { uri: string; headers?: Record<string, string> };
  startSeconds?: number;
  audioTrack?: number;
  subtitleTrack?: number; // -1 = off
  speed?: number; // 1 = normal
  subtitleScale?: number; // 1 = normal
  subtitleDelay?: number; // seconds, 0 = as in the file, positive = later
  zoom?: VideoZoom; // "fit" (default) = whole picture, "fill" = covers the view, crops
  aspect?: number; // picture width / height as shown, if known: subtitles keep their size on a wide picture
  paused?: boolean;
  externalSubs?: { uri: string; lang?: string; title?: string }[];
  onLoad?(e: { duration: number; audio: Track[]; subs: Track[] }): void; // sidecars may not be listed yet
  onTracks?(e: { audio: Track[]; subs: Track[] }): void; // once per load: full list, every sidecar added or failed
  onProgress?(e: { position: number; duration: number }): void;
  onEnd?(): void; // end of file: last frame held, paused; play replays from 0, a seek moves away
  onBuffering?(buffering: boolean): void; // waiting for data: stalled stream, seek, reload
  onError?(msg: string): void;
};
export type PlayerRef = { seek(s: number): void; play(): void; pause(): void };
```

## Rules

- Keep playback position in a ref, not state.
- Keep `PlayerEngine` free of mpv-specific concepts (a second engine may come later).
- Sources (`src/playback.ts`, pure): `getPlaybackInfo` (`src/api.ts`, body = `playbackInfoBody(mediaSourceId)` with `DEVICE_PROFILE`) → `playSource` picks the requested version (else the first), refuses on `ErrorCode` (`NotAllowed` → its own message) or `SupportsDirectPlay` not true, and returns `{source: {uri, headers}, externalSubs, playSessionId, audio, subtitles, defaultAudio, defaultSubtitle}` (defaults as Jellyfin indexes) - static stream URL, sidecar text subtitles (srt / subrip → `.srt`, ass / ssa → `.ass`, vtt → `.vtt`; image sidecars skipped - a `defaultSubtitle` pointing at one has no track to match) built in the client, never `DeliveryUrl`. mpv gets the token-only header `streamAuthHeader` (I1). Errors: `playErrorMessage`.
- Resume: no prompt - every play entry point says what it does (Apple TV style): detail Resume + Play from Start, series Resume Episode + Play from Start, episode card ▶ resumes (Play from Start in its ⋯ menu), autoplay starts the next from its resume point. Home / Library cards open the detail, never the player. Resume / start-over choices only show when the item has a server resume point (server keeps 5-90%, items ≥ 5 min).
- Reporting (`src/player/useReporting.ts`, bodies from `playbackReport` in `src/playback.ts`): `Sessions/Playing` once mpv loaded the file (sets LastPlayedDate + PlayCount), `Progress` every 10 s (paused too, with `IsPaused` - the server ends sessions that stop checking in) + on pause / unpause / seek / track change / app going to the background (resume rules apply on every `Progress`), all with the audio / subtitle playing (see Tracks), `Stopped` with the last position when the load ends (close, Retry, error), all with `PlaySessionId`, `PlayMethod: DirectPlay`, sent in order per session (one queue: a late `Progress` never lands after `Stopped`). After `Stopped` the fetch cache refetches (resume point, Continue Watching, Next Up). Best effort: failed reports are dropped (offline progress: `docs/context/sync.md`).
- mpv adapter (`src/player/mpv.tsx`, the only importer of `modules/mpv`): a new `source` object = a new load; start, autoplay and first audio / subtitle track are read at that moment, later `paused` / track changes call mpv. `onLoad` fires once per load on mpv's first tracks-ready with duration + tracks (mpv track ids; sidecar subs may not be listed yet). `onTracks` fires once per load with the full list: on the native `isReadyToSeek` (sent after `FILE_LOADED`, once the sidecars were `sub-add`ed or failed), from a track read started after it; a same-URL load (I4) sends it right away. Known limit: the native event has no load generation, so a source change before the previous file opened could take that file's late ready-to-seek as this load's. Sidecar tracks carry `external` = mpv's `external-filename`. Only a new `source` is a new load. End (I8): the native `onPlaybackEnd` (mpv `eof-reached`, `keep-open=always` on both platforms) becomes a last `onProgress` at the duration + `onEnd` once per end, once the load is ready - an EOF of the previous file is dropped (native load guard + JS `ready`), never gated on playing (mpv pauses itself at EOF). After the end `play()` / `paused=false` seeks to 0 first, unless a seek (ours, or progress from a lock-screen seek) moved away. Early end (I11): an end more than 5 s before the duration (by mpv's own position - progress is throttled and misses lock-screen seeks) is a stream that gave up after a long network drop, not the end - no `onEnd`; the adapter reloads the source at that position with the current tracks on the same native view (`reload: true` in the source - the view otherwise skips a source with the URL it already has; never a remount, which would run two engines and the old one's teardown clears Now Playing + the audio session). An early end again with no progress past where that load (or our last seek) started is `onError` (network still gone, or a file cut short - never marked played). A second end event while one is checked, or before the reload's tracks are ready, is dropped; a pause made during the reload is applied once it is ready. `onBuffering` passes mpv's loading state on (load, seek, paused for cache), plus `true` when an early end reloads. Demuxer cache caps 100 / 32 MiB (`cacheConfig`, 4K remux memory). Never call `destroy()` on unmount: the native view tears mpv down itself (iOS `deinit`, Android detach); on iOS `destroy()` stops and restarts mpv for view reuse - wasted work before the view goes away.
- Player screen (`src/app/player.tsx`, params `id` + `start`): PlaybackInfo → `playSource` (aborted on leave, keyed per account + item + attempt), spinner until the player's `onLoad` or `onError` (no load timeout - a failed open is mpv's own error, I15), and again while the engine waits for data for more than 0.5 s (`onBuffering`, `STALL_SPINNER_MS` - quick seeks don't flash it), refusal / load / playback errors as `Message` + Retry; Retry reloads from the last progress position. End of file: `paused` (the pause report sends the end - the server marks it played), controls up; Play replays.
- Up Next (episodes): the player fetches `nextEpisodes` for the item (`docs/context/api.md`). In the last 30 s (`UP_NEXT_SECONDS`, `upNextCountdown`) an `UpNext` glass tile shows bottom right, Apple TV style - the next still with a ring (`AnimatedProgressRing`) around ▶ that fills smoothly as the countdown runs (UI-thread `withTiming` to full over the real time left, scaled by speed; re-synced to the exact position on every progress update, stopped while paused or waiting for data; Reduce Motion: steps with the updates), "Up Next · 12s", "S1, E2 · Title"; the tile is Play Now, a small ✕ on the still's corner hides it (hit slop to 44 pt) - in the screen's bottom stack (`PlayerBottom`), above the scrubber panel (`PlayerScrubber`) while the controls are up; it stays mounted while they come and go (the ring keeps running) and steps aside during a pull to close (glass can't fade with the video); VoiceOver hears "Up next" once per next episode, also when seeks leave and re-enter the window. At the end (`onEnd`), or on Play Now, the same screen plays the next episode (`router.setParams` `id` + `start` = its resume point, no new modal): the finished one gets its `Stopped` at the position it reached (the position resets only in a setup effect, after the reporting cleanup), the next loads unpaused from its own resume point (else 0), the tracks menu closes and a drag cut short by the end is dropped (`scrubbing` off); speed stays (subtitle size is a setting), audio / subtitle choices are kept with the id of the item they were picked on (Jellyfin indexes of that file) and carry to the next one by language (see Tracks). Hide = no autoplay for this episode; the end then pauses as for a movie. Last episode / movies: no card. No "Still watching?" limit yet.
- Player UI (`src/app/player.tsx` + `PlayerControls`), Apple TV style: video only until a tap; the overlay hides after 3 s, never while paused, scrubbing or with a screen reader on. Controls sit on glass (`Glass`: Liquid Glass on iOS 26+, translucent elsewhere), no dimming layer: close chevron-down + title pill on top, ⟲10 / play-pause (large) / 10⟳, scrubber panel with elapsed / remaining. Before playback starts (loading / error) only the top bar shows. Status bar hides with the overlay. Rotates freely; every other screen stays upright portrait (`expo-screen-orientation`: the player unlocks on mount, re-locks `PORTRAIT_UP` on unmount).
- Zoom (`src/settings.ts` `videoZoom`, same for every account; Apple TV style): fit (default) or fill, landscape only - portrait always fits and has no button (fill would crop most of the picture). Top-bar button next to "⋯" ("Fill screen" / "Fit to screen") or a pinch (apart past 1.1 = fill, together under 0.9 = fit, on release; `zoomAfterPinch`). Fit insets the video view by the safe area on the long sides, the same on both so the picture stays centred (`videoFrame`: clear of the notch / Dynamic Island; landscape keeps the full height, so the home indicator may overlap the picture's bottom edge); fill covers the screen. Engine: `zoom` prop → native `setZoomedToFill` (iOS display layer `resizeAspectFill`, Android mpv `panscan=1`); iOS PiP drops to fit while in PiP. The iOS Simulator sizes the display layer to the picture, so fill shows no change there - check on a device. A pull that fails (a second finger lands) springs back, never closes; a cancelled pinch keeps the zoom.
- Gestures (gesture-handler, own `GestureHandlerRootView` in the modal): single tap toggles the overlay (only while playing - before that the top bar is always up), pinch = zoom (landscape, races the rest; the pull is one finger only), double-tap left / right half = ±10s (both on JS, `runOnJS`). Pull down to close runs on the UI thread (reanimated worklets): the video follows the finger, shrinks, fades (to 35%) and rounds its corners, the player's own black backdrop fades so the screen below shows through (the route is a `transparentModal`); past 120 pt a "Release to close" pill shows, dragging back up hides it; release past it (or a flick) slides out and closes, otherwise it springs back. Sideways drags fail the pull (scrubber).
- Tracks (`playSource` → `audio` / `subtitles` as `TrackOption {id, index, label, lang, forced}`): `id` is mpv's track id, predicted from Jellyfin's streams before load - each type numbered from 1 in file order (embedded), then the sidecar subtitles in the order they're added (`externalSubs`; image sidecars aren't loaded and get no id). Jellyfin lists sidecars first (`#0`), so never use its index as an mpv id. Once the engine sends its full list (`onTracks`), `matchTracks` replaces the prediction (a stream mpv drops or a sidecar that fails to load would shift ids): sidecars by URI, a type's embedded tracks by position when the counts agree, else in order by language (`und` = any; none lining up = by position; best effort: same-language tracks or `ger` / `deu` can pair wrong - mpv's `ff-index` would be exact but needs a native change for audio); options with no track leave the menu. The first selection still goes in as the predicted id (`initialSubtitleId`), so a missing sidecar default can show the wrong track until `onTracks` corrects it (a moment; not seen on iPhone, B14). Choices are Jellyfin indexes (`TracksValue`), resolved to mpv ids against the current options - a choice the file doesn't have falls back to the first audio / subtitles off. The player starts with the server's defaults (`DefaultAudio/SubtitleStreamIndex`: what was last played on this item, else the user's language preferences); no default subtitle = off. Remembered per user: every report carries the audio / subtitle chosen (`AudioStreamIndex` / `SubtitleStreamIndex`, Jellyfin indexes, -1 = off: the pick, carried pick or default - never the fallback for a track that failed to load, so a sidecar that failed once isn't remembered as off) and a change sends a `Progress` (`AudioTrackChange` / `SubtitleTrackChange`) - the server keeps them per item (`docs/context/api.md`), not across episodes. Next episode in the same player (autoplay, Play Now): a pick carries by language (`carryTracks`, the picked track's language + label; `TrackPick`) - the track with the same language and label, else the first in that language that is forced-only as the pick was (`IsForced`: full subtitles don't turn into forced ones), else the first in that language, a pick without a language only by its label; subtitles off stay off; no match or nothing picked = that episode's server defaults. Resolved against the server's track list (stable for the load), not the engine-matched one. Carried picks beat the next episode's own remembered tracks, and keep carrying until a new pick. Best effort: language codes that differ between files (`ger` / `deu`) don't match. Not carried to an episode opened later from the detail screen (the server's per-item memory and language preferences apply). Labels are Jellyfin's `DisplayTitle` (else Title / Language / Codec) without "Default". Tracks menu (`TracksMenu` on `ActionSheet`, top-bar "⋯" button, spoken "Audio, subtitles and speed", keeps the controls up while open): Audio, Subtitles (incl. Off and sidecars), Speed (0.5-2×), Subtitle size (Small 0.8 - Extra large 1.5; portrait sends it 1.25x larger - mpv sizes text to the picture, which is small in portrait: `subtitleScaleFor`; in landscape the text keeps the view's height whatever the picture's shape: Android sizes it to the view itself, on iOS mpv draws it into the picture, so the adapter multiplies the scale by view height / picture height - `frameSubtitleScale`, from its own layout, `zoom` and `aspect` = `pictureAspect`: the server's `AspectRatio`, else Width / Height; clamped 0.5-2; known limit: JS doesn't see PiP, which keeps the landscape factor - PiP is post-MVP). Choices last for the screen (survive Retry; the menu itself closes). Subtitle size is remembered on the phone (`src/settings.ts` `subtitleScale`, same for every account): the player starts with it, a menu change saves it. Speed is not remembered (1× on every open). Subtitle timing (shown while subtitles are on): a slider on the sheet (`TimingSlider`, plain views like the scrubber; closes with Done) - 10 s earlier (left) to 10 s later (right), in sync in the middle, 0.1 s steps (`clampDelay`, `delayAt`); a drag applies on release, − / + move 0.1 s, Reset goes back in sync; VoiceOver: adjustable, swipe up / down = 0.1 s (`subtitleDelay` prop, seconds, positive = later; mpv `sub-delay` via the module's `setSubtitleDelay`, both platforms), "In sync" by default; it lasts for the item and subtitle track (survives Retry; back to in sync on another subtitle pick, off included, and on the next episode - each file is off by its own amount), not remembered or reported (Jellyfin has no field for it). Speed, subtitle size, subtitle timing and zoom are mpv-wide: the adapter sends them on change and again on every load (Android has no renderer before the file loads).
- Scrubber seeks on release (shows the drag position meanwhile); VoiceOver: adjustable, swipe up / down = ±10s, escape gesture closes. Position + duration live in `src/player/progress.ts` (not React state).
- Known engine issues (details + fix directions in the test plan): I3 stale first progress after a new load (handled: progress dropped until that load's tracks are ready), I4 same URL ignored (handled: same URL in a new source → `seekTo(start)` + `play()`), I8 end event (handled: `onEnd`, see the adapter rule above), I11 premature EOF after long network drops (handled: longer reconnect window natively + reload at the stopped position, see the adapter rule above).
- Seeks: `seek(s)` (scrubber, lock-screen position) and the resume `start` land on the exact frame; ±10s skips (`seekBy`: buttons, PiP, lock screen) snap to the nearest keyframe (fast) - `hr-seek=absolute`, `docs/context/mpv.md`.

# mpv native module

Read before working on `modules/mpv/` (native player code, `app.plugin.js`, binaries). Vendored MPL-2.0 module: upstream, commit, local changes and binaries in [`app/modules/mpv/UPSTREAM.md`](../../app/modules/mpv/UPSTREAM.md). `app.plugin.js` is our own (GPL-3.0-or-later).

## Rules

- Vendored files keep their headers and stay diffable against upstream (excluded from Prettier). Record every local change in `UPSTREAM.md`; sync with `/update-modules`.
- After any native change, MPVKit / libmpv bump or upstream sync: run the device test plan [`docs/test-plans/mpv.md`](../test-plans/mpv.md) on a physical iPhone and Android phone.
- Binaries: MPVKit (iOS, podspec URL in `app.plugin.js`) and `dev.jdtech.mpv:libmpv` (Android, `android/build.gradle`) are GPL builds today; LGPL rebuild post-MVP (root §7, `docs/open-items.md`). Update `THIRD_PARTY_NOTICES.md` with every binary change.
- Android NDK: `app.plugin.js` pins `ndkVersion` to the NDK libmpv was built with (`LIBMPV_NDK_VERSION`). An older app NDK packs an older `libc++_shared.so` and libmpv fails to load (I9). Re-check on every libmpv / RN bump: `strings libmpv.so | grep "clang version"`.
- Release builds keep the JNI classes via libmpv's consumer rule (`-keep class dev.jdtech.mpv.MPVLib { *; }`); verify playback on a release build after bumps.
- Logs (I13): mpv logs every property set with its value at `v` (`Set property: name=value`), and libmpv on Android requests `v` and prints every message to logcat itself. Anything secret (`http-header-fields` with the token) goes through the option API (`mpv_set_option_string` / `setOptionString`, logged at `debug` only) - never as a property. iOS requests `info` and redacts `Token=` before forwarding to the app log. Never request `debug` or lower.
- Network options (I11, both platforms, set before init): `network-timeout=15`, `stream-lavf-o=reconnect=1,reconnect_on_network_error=1,reconnect_delay_max=10`. FFmpeg 8 (MPVKit av5: libavformat 62) nests two retry loops - each retry of a dropped read reopens the connection, and that open retries the connect the same way. Each loop waits 0, 1, 3, 7, 15... s and gives up once the next wait is over the max: any max 7-14 = waits up to 7 s, ~55 s in all, back within ~7 s of the server; 15-30 adds the 15 s step (~2.5 min, back within ~15-30 s - tested, too slow). A drop past the window ends the stream early at the end of the cache - the JS adapter reloads it on the same view with `reload: true` in the source (local change: forces the load past the view's same-URL skip; iOS `loadVideo(config:force:)`, Android `VideoLoadConfig.reload`) (`docs/context/player.md`). Demuxer caps (100 / 32 MiB) come from JS per load (`cacheConfig`). mpv's loading state (`isLoading` in `onPlaybackStateChange`: load, seek, `paused-for-cache`) drives the player's buffering spinner.
- `hr-seek=absolute` + `hr-seek-framedrop=yes` on both platforms: absolute seeks (`seekTo`, `start`) decode up to the exact frame, relative seeks (`seekBy`, ±10s) snap to a keyframe. Android upstream had `hr-seek=no` (every seek keyframe-snapped).
- Subtitle fonts (I6): iOS libass can't open system font files, so the app bundles Noto (Sans, Serif, Sans Mono, Arabic, Hebrew + CJK SC, +~18 MB; `app.json` `expo-font` `ios.fonts`, provenance in `THIRD_PARTY_NOTICES.md`). The renderer links them into `<config-dir>/fonts` (CJK SC as `subfont.ttf`, the last resort) before init; a bundled name missing from `subtitleFontResources` / `app.json` logs `Bundled subtitle font ... is missing`. Android's libass reads `/system/fonts` (fontconfig) - no bundled fonts. Style (`setSubtitleStyle`: font, colour, `edge` - local change) applies to text subtitles only. Edge: `outline` = `sub-border-size=3` black, shadow 0; `shadow` = border 0, `sub-shadow-offset=2` `#C0000000`; `box` = `sub-border-style=background-box`, `sub-back-color=#99000000`, border 0, shadow offset 12 (the box padding, as upstream). Each edge sets every part it uses, so switching back undoes the others; `sub-ass-override` stays mpv's default (`scale`).
- `keep-open=always` on both platforms: at EOF mpv pauses on the last frame (seek back works). The end is the `eof-reached` property -> `onPlaybackEnd` view event, dropped while a new load is pending (iOS load generation, Android `isReadyToSeek` - false from `load()` to `FILE_LOADED`); on iOS the engine also takes its own pause state along (PiP, Now Playing). `END_FILE` only means stop / replace / error (I8).
- Failed open (I15): `END_FILE` -> `onError`, dropped for an older load. iOS: reason `error` (message = `mpv_error_string`), load generation as for the end. Android: the libmpv wrapper passes no reason, so the renderer keeps its own load generation (`load()` / `stop()` bump it before mpv's `stop`, `START_FILE` takes it) and an `END_FILE` of the current load without `eof-reached` is the error. Never issue mpv `stop` / `loadfile` on Android without bumping it. Known limit (both platforms, as for the end): a `loadfile` that mpv drops before `START_FILE` (two loads within moments) shifts the queue and that screen's later errors are dropped - JS only reloads on Retry / a new item, so not seen in practice. Root fix when libmpv is rebuilt (LGPL, post-MVP): pass the `END_FILE` reason through the JNI event callback, then Android checks `reason == error` like iOS.
- iOS background (I2): VideoToolbox is invalidated in background and mpv would fall back to software decoding for the rest of the file. The engine sets `vid=no` on `didEnterBackground` and `vid=auto` on `didBecomeActive` (not in PiP; local change, `MPVLayerRenderer` `disableVideoForBackground` / `restoreVideoAfterForeground`) - the decoder restarts with hwdec from mpv's refresh seek. The JS player pauses in the background (`docs/context/player.md`); `UIBackgroundModes: audio` (`app.json`) lets lock-screen Play carry on with audio only (video track off until foreground). Remote play / pause / toggle (lock screen, Control Center, headphones) and an audio interruption (a call) go through the engine's `playFromOutside`, which acts first and then sends the `onOutsidePause` view event (`isPaused`) so the JS screen follows (local change). A stale interruption iOS delivers when a suspended app wakes (`WasSuspended` / reason `appWasSuspended`) is ignored. The engine also pauses natively on `didEnterBackground` (iOS as tvOS, not in PiP) so audio never runs on until JS pauses. PiP auto-start is off on every load (PiP is post-MVP; with the `audio` mode iOS would otherwise start it when the app is left). The bounded decoder reset (display layer `.failed` KVO) stays as the fallback.

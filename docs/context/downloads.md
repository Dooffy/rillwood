# Downloads (store + native module contract)

Read before working on `src/downloads.ts` (store, hooks, reconcile, cleanup, storage), `modules/downloads/` or the Downloads screen. The native module `modules/downloads/` (M5) is the only thing that talks to the OS; only `src/downloads.ts` imports it. Design + sources: [`docs/research/background-downloads.md`](../research/background-downloads.md).

## Native module

Own Expo module (Swift + Kotlin, Expo Modules API) - no third-party downloader, no system `DownloadManager` (can't resume without ETag). Native owns the queue, order, concurrency (max 2), network rule and retry.

- iOS: one background `URLSession`, whole batch handed over at once (avoids the background resume rate limiter); force-quit cancels transfers → re-enqueue on next launch.
- Android 14+: one user-initiated data transfer (UIDT) job as queue runner. Android 8-13 (and 14+ when the job is refused): WorkManager unique worker + `dataSync` FGS.
- Network setting (Settings → Downloads → Network, `settings.downloadNetwork`, Wi-Fi only default / Any network): iOS `allowsCellularAccess` (+ `allowsExpensiveNetworkAccess`), Android UIDT `setRequiredNetworkType` / WorkManager `UNMETERED` vs `CONNECTED`. Wi-Fi only = unmetered. No NetInfo.

Contract (types, calls, events): [`app/modules/downloads/index.ts`](../../app/modules/downloads/index.ts), native module name `Downloads`. `import Downloads from '../../modules/downloads'`, events via `Downloads.addListener('progress' | 'done' | 'error' | 'waiting', fn)`.

- `dest` is relative to `Paths.document`; native resolves it under Documents and rejects anything that ends up outside (it re-reads `dest` after process death, without JS). `size` (`MediaSource.Size`) is required - the store's pre-flight skips items without one, so one episode can't block a season.
- `enqueue` items and options are typed `Record`s on both platforms (`EnqueueItem`, `EnqueueOptions`) - the bridge checks field types.
- iOS (`ios/DownloadsSession.swift`, mechanics in the code comments): background session id `app.rillwood.client.downloads`, started at launch by `DownloadsAppDelegateSubscriber` (also on a background relaunch, before JS). The subscriber answers `handleEventsForBackgroundURLSession` for other ids straight away (Expo waits for every subscriber).
  - State: `Application Support/Downloads` (`state.json` versioned + `<id>.resume`), excluded from backup, protected until first unlock. Finished records are removed (JS reconcile finds the file).
  - Credentials: Keychain per account (after first unlock, this device only). No credential → `paused(auth)`.
  - Concurrency: `httpMaximumConnectionsPerHost = 2` - max 2 per server (two servers = up to 4); the daemon doesn't guarantee order within a batch.
  - Retry (5xx, network errors): 3 attempts after 5 s, 30 s, 120 s via `earliestBeginDate` (the daemon holds the delay, also while the app is suspended or dead); the budget resets once bytes flow again; then `error(network)` / `error(system)`. Write errors / disk full → `error(storage)`, 404 / 416 / other status → `error(system)`, no retry (the daemon does the Range resume).
  - Resume data replays the original request incl. the auth header: after a token change (401) the download restarts from 0 with the new credential. Sign-out / removal cancels the account's unfinished tasks so no resume data keeps the old header (JS `stopAccount`).
  - `state.json` unreadable (before first unlock) or from a newer version: nothing is overwritten and live tasks are kept.
  - Force-quit: on the next launch the tasks fail with the force-quit reason → restarted at once from their resume data.
  - Network wait: the daemon holds a task the rule blocks without telling the app. `NWPathMonitor` (on the session queue, from `start()`) works out why: path not satisfied, or Wi-Fi only on an expensive path (cellular, hotspot) → active tasks get `queued` + `reason: network` and a `waiting` event; back → reason cleared, `waiting` event. One place decides (`updateNetworkWait`: path update, rule change, every task start), events only on a change; bytes flowing clear it too (JS on `progress`). A stale value after a relaunch is fixed by the first path update, before JS reconciles. A connection error while the path is blocked restarts the task after 30 s without using a retry (the daemon waits for the network; the delay avoids a loop if the default path isn't the server's route - e.g. a LAN-only Wi-Fi with Wi-Fi Assist). Low Data Mode doesn't block (requests allow constrained access).
  - Network rule (decided 2026-10-09): per request (`allowsCellularAccess`, `allowsExpensiveNetworkAccess`). A change moves running tasks: cancel, restart under the new rule. Resume data replays the old rule, so running files restart from 0 - shipped as is for MVP; two sessions (rule on the session) would keep progress (`docs/open-items.md`).
- Android (`android/src/main/java/app/rillwood/downloads/`, mechanics in the code comments): `DownloadsQueue` (one handler thread for every state change, transfers on their own threads) runs `DownloadsTransfer` (OkHttp - RN's 4.9.2, `compileOnly`, never 5.x). Started by the module's `OnCreate` or a runner. A runner (`DownloadsRunner`: the UIDT job on 14+, the WorkManager worker on 8-13) keeps the process alive in the background and starts the queue again without JS; one attached at a time.
  - State: `noBackupFilesDir/downloads/state.json` (versioned, `AtomicFile`), never backed up. Records keep the file's `Last-Modified` for `If-Range`; no byte count (the `.part` length is the offset). Running records are queued again at launch; a bad record is dropped (JS re-enqueues). Unreadable / newer version: nothing is written over it, new downloads end in `error(system)`.
  - Credentials (decided 2026-10-10): one file `noBackupFilesDir/downloads/credentials`, AES-GCM with a key in the Android Keystore (this device only). Unreadable → read again next time; still unreadable (key gone) → `paused(auth)` until JS sets them again (the file starts over).
  - `dest` resolves under `filesDir` (= `Paths.document`), canonical path checked; the file is written to `<dest>.part`, fsynced, renamed at `size`. A `.part` without a `Last-Modified` starts over.
  - Concurrency: max 2 at a time over all servers, in enqueue order (a stopping transfer keeps its slot until its thread ends).
  - Retry (5xx, connection errors, a body that ends early): 3 attempts after 5 s, 30 s, 120 s (in memory - a relaunch starts at once); the budget resets once bytes flow; then `error(network)` / `error(system)`. Write errors → `error(storage)`; 404 / other status / size mismatch → `error(system)`; 416 → `.part` deleted, start again.
  - Network wait + rule: default network callback (`ACCESS_NETWORK_STATE`, in the module manifest). No network, or Wi-Fi only on a metered network → active tasks `queued` + `reason: network`, `waiting` event, running transfers stopped (the `.part` stays, no retry used); back → started again from the `.part`. A rule change takes effect at once and keeps the progress.
  - Android 14+ runner (`DownloadsJobService`): one user-initiated data transfer job, `setPersisted` (`RECEIVE_BOOT_COMPLETED`), estimated / transferred bytes reported. One job ID per network rule (`NETWORK_TYPE_UNMETERED` Wi-Fi only / `NETWORK_TYPE_ANY`); a rule change cancels the other one. After every queue change: work left, no job attached and the app on screen (module foreground / background events; a UIDT job can only be scheduled then) → scheduled unless already pending / running (scheduling a running ID would stop it); nothing active (all done / paused / failed) and no transfer thread left → `jobFinished`. Work restored at launch is scheduled once the app is on screen; in the background without a job the queue runs in-process until the next open. Byte counts for the system only grow (transferred = what left the remaining bytes since the job started). `onStopJob`: constraint / thermal / memory → rescheduled by the system; Task Manager stop (also ends the process) → every active download `paused(user)`, saved before `onStopJob` returns (`error` event per item, JS didn't ask), no reschedule.
  - Android 8-13 runner (`DownloadsWorker`, `androidx.work:work-runtime-ktx` 2.12, decided 2026-10-11): a `CoroutineWorker` that checks the queue has active work (an extra appended worker ends at once, no foreground service), calls `setForeground` (`dataSync`, own notification ID - WorkManager cancels it when the worker ends; `SystemForegroundService` merged with that type in the module manifest + `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC`), then waits until the queue finishes it. One unique work name per network rule (`UNMETERED` Wi-Fi only / `CONNECTED`), `APPEND_OR_REPLACE` (a worker just finished may not have returned, one that started the process not attached yet - the extra one ends at once). Enqueued once per rule while work is left, in the background too (WorkManager starts it later - constraint, reboot, process death); finished when nothing is active. Stopped by WorkManager (constraint lost, timeout) → detached, WorkManager runs it again; Task Manager stop (12+, `STOP_REASON_USER`) → every active download `paused(user)`, like the job. Started in the background on 12-13 (no foreground service allowed): runs as a plain job (about 10 min, then re-run) without a notification - a notification without the service would outlive the process. Also the fallback on 14+ when `schedule` throws or returns `RESULT_FAILURE` (OEM): the job is tried again on the next schedule; there the 15+ `dataSync` 6 h / 24 h cap applies (WorkManager handles the timeout).
  - Runner changes: one attached at a time (a second one ends the first). A rule change keeps the old rule's runner until one for the new rule is scheduled (14+ in the background: until the next open), then ends it; the other rule's job / work is cancelled.
  - Notification (`DownloadsNotification`, channel `downloads`, low importance): set within 10 s of every job start (the worker: with `setForeground`), then every second: "Downloading N items", "<done> of <total>" + progress bar over the active downloads, or "Waiting for Wi-Fi" / "Waiting for network"; tap opens the app; Pause action → every active download `paused(user)` (`error` event per item). Without the notification permission it's only in Task Manager; downloads run either way. The permission (Android 13+) is asked once per install, right after the first download starts (`src/notificationPermission.ts`, from `useDownloadControl`); a prompt that can't show (no activity) is tried again with the next download.
- Tokens never in URLs or logs. Native keeps them only in OS-protected storage so transfers resume after process death without JS (iOS: Keychain + the background session's resume data; Android: the Keystore-encrypted credential file). This is the only exception to "tokens only in `expo-secure-store`" (root §2).
- HTTP: never HEAD (405); total from `Content-Range` / `Content-Length`, checked against `MediaSource.Size`. Resume = `Range: bytes=<n>-` + `If-Range: <Last-Modified>`; 206 with another start → fail, 200 → file changed, restart; 416 → iOS `error(system)`, Android start again (a full `.part` is finished without a request). Finalize only when size == total (`.part` → rename). iOS: check the HTTP status in `didFinishDownloadingTo` (error bodies "finish" too).
- Status: 401 → `paused(auth)`, 403 → error (user policy `EnableContentDownloading` off - hide Download), 404 → failed, 5xx / IO → native retry with backoff.

## Store (`src/downloads.ts`)

- Index in kv-store key `dl`: `{ version: 1, items }` (`Download` in `src/downloads.ts`); an unknown version or bad JSON starts empty and isn't overwritten, and reconcile then doesn't cancel native tasks - migrations go in `store()` when the version moves on. Watched / progress fields come with offload + sync (M6).
- File `downloads/<accountId>/<itemId>/<sourceId>.<container>` (server ids cleaned to `[A-Za-z0-9_-]` - no `/`, no `..`; deleting the item's last version removes its whole folder, snapshot included); URL `/Items/<sourceId>/Download` (an alternate version is an item of its own).
- Hooks: `useDownload(id)` = live progress; `useDownloadList()` = structure only (add, remove, status). Progress stays in memory; kv-store is written on any change but progress (`bytes`).
- Start: `startDownloads(requests)` for the active account, one native `enqueue` per account (a season = one call); skips items in the index and sources without a size; a batch native rejects ends in `error`. Pre-flight (only when something new starts): free space minus everything still to download stays above max(2 GB, 5% of the disk). Free space = `getFreeDiskStorageAsync` (`expo-file-system/legacy`; iOS `volumeAvailableCapacityForImportantUsage`, purgeable space included, as Settings shows it) - `Paths.availableDiskSpace` (`systemFreeSize`) leaves purgeable space out and refused a 4 GB movie with 120 GB free; it's only the fallback. `startDownloads` is async for it.
- Native `error` event carries the stopped `state` + `reason` (paused for auth / failed) - JS applies it like `done`, no reconcile.
- `reconcile()` (`initDownloads`: launch + back from the background, not a quick switch; one at a time): mirror native state; no task + full-size file → `done` (any status); no task + queued / downloading → re-send; paused / failed without a task wait for resume; unknown native tasks → `cancel`.
- Credentials follow the session (`subscribeSession`): native holds the header of each signed-in account with downloads, cleared on sign-out / removal (also once its downloads are gone); only changes are sent.
- Sign-out / removal in this run (also a 401 sign-out) stops the account's unfinished downloads (`stopAccount`) → `paused(auth)`, done ones stay, other accounts untouched. iOS: native `cancel` (resume data holds the header; starts from 0 after sign-in). Android: native `pause` (the `.part` has no header; resume keeps the progress). Resume after sign-in is the user's (row / menu). Not an account that boots signed out (token unreadable, e.g. keychain locked): it keeps its tasks.
- Network: `enqueue` passes the setting (`cellular` = Any network); `initDownloads` sends it with `setCellular` at launch (native keeps its own copy) and again on every change.
- Storage limit (Settings → Downloads → Storage limit, `/download-storage`, `settings.downloadLimit`): decimal GB, 0 = no limit (default). Phone-wide, every account together. Checked at start before the free-space pre-flight: the full size of every download in the index (done, queued, paused, failed) + the new batch must stay within it, else `problem: 'limit'` (toast). Only gates new starts - lowering it deletes nothing, resume isn't checked. Slider stops (`downloadLimitSteps`): 5 GB-2 TB below 90% of `Paths.totalDiskSpace`, then No limit; a limit saved on a bigger phone shows as itself until moved.
- Groups: `seasonId` saved per episode; `downloadGroup(accountId, { itemId } | { seasonId })` keys an account's downloads of an item / season, listeners are keyed by it (a progress event wakes only its item's and season's hooks). `useDownloadSummary(group)` = live state (downloading over paused / failed over done, progress over every byte, distinct `items`); `useHasDownloads(group)` = boolean, no re-render on progress; `pauseDownloads` / `resumeDownloads` (one native batch) / `deleteDownloads`.

## Download button (`src/useDownloadControl.ts`, `DownloadButton`, item menu)

- Where: detail header right (movie, episode), series header right (the shown season: "Download Season n"), item menu (movies, episodes, videos, seasons; shows none - a season at a time).
- `useCanDownload(item)` (header gate, boolean): shown when `GET /Users/Me` says `Policy.EnableContentDownloading` (cached `useFetch`), or when something of it is already downloaded (so it can be deleted). Hidden = no `headerRight` at all (`DetailHeader`): a header button that renders nothing still gets an empty glass button on iOS.
- States: ↓ → spinner while the files are looked up → ring with stop square (downloading) / arrow (paused or failed) → ✓ (tap asks, then deletes). A ring tap only opens the menu (never pauses by itself): the same `downloadActions` as the item menu, titled with the item. Menu (`downloadActions` in `useDownloadControl.ts`): Download; Pause Download (downloading) or Resume Download (paused / failed; a partial season: Download the rest) + Cancel Download (red) + Delete Download when part of the group is done (a season); Delete Download when done (a partial season: Download first).
- Cancel Download (`cancelDownloads`): stops the group's unfinished downloads and deletes them with their partial files at once - picking it from the menu is the confirmation; done ones stay. Delete Download (`confirmDeleteDownloads`) removes everything and asks first.
- Start: a movie / episode from a card has no `MediaSources` → `GET /Items/{id}` first; a season → `/Shows/{id}/Episodes?seasonId&fields=MediaSources,Overview&isMissing=false` (`seasonFiles`). First version of each item (what Play picks). Toasts: lookup failed (also a season without `SeriesId`), 403 ("This account isn't allowed to download."), no space (pre-flight), nothing with a `Size` to download. Account switched mid-lookup or during the free-space read → dropped. Start also resumes the requested items' paused / failed downloads.
- Partial season (`partial`): once the season has downloads, `seasonFiles` is fetched; an episode with a file and a `Size` that isn't in the group = partial. Not downloading + partial → ↓ (header) / Download + Cancel + Delete Download (menu; Pause + Cancel + Delete while downloading): downloads the rest, resumes the paused. Episodes without a `Size` never count (they can't be downloaded). File list unknown (loading, offline) → treated as complete.
- A 403 from native (policy turned off after the start) ends as failed (arrow = retry, fails again). The button stays while the item has downloads (to delete them); items without downloads hide once `/Users/Me` refetches.
- Snapshot (`src/downloadSnapshot.ts`), in the item folder next to the video, saved when a download starts: `item.json` (the item DTO, always with the downloaded version in `MediaSources`; shared by the item's versions), `poster.jpg` (`posterImage`, 720 px), `backdrop.jpg` (`backdropImage`, 1920 px), external text subtitles of the version `<source>.sub-<index>.<ext>` (`subtitleUrl` / `subtitleExtension`; image formats stay in the video). Images and subtitle streams are served without auth - no token in these requests. One snapshot at a time per item folder (versions share the JSON + images; files already there are kept). Partial counts (a subtitle the server lost doesn't block it); only all-failed (offline) leaves `snapshot` unset. Retries: after each reconcile, one at a time, the round ends at the first failure; from `item.json`, else `GET /Items/{id}` when signed in. These small fetches don't follow Wi-Fi only (that's for the video). Delete (`removeFiles`): the item's last version takes the whole folder, else only its video + `.sub-` files; also run when a download is deleted while its snapshot saves. `readSnapshotItem(path)` = the item for offline detail (M6).
- Files app (iOS): opt-in dev builds share `Documents` - `RILLWOOD_FILE_SHARING=1 npx expo prebuild -p ios` (`app/app.config.ts` adds `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`), then On My iPhone → Rillwood → `downloads/<account>/<item>/`. Every other build stays private (it would also show `SQLite`); user-facing sharing is a post-MVP decision (`docs/open-items.md`).
- iOS: native marks `Documents/downloads` `isExcludedFromBackup` at launch (covers the snapshots), and each finished video file.
- `cleanup()` on launch + foreground: delete when `now > expires_at`, skip pinned / currently playing / active; weekly orphan sweep.
- Offload policy setting: Off / After watched (default) / After download; delay 0/7/14/30 days (default 7). Watched = local ≥90% or server `UserData.Played`.
- Device test plan (M5): `docs/test-plans/downloads.md` (scaffold rows done) - force-quit, OS kill, reboot, airplane mode, 20GB + 60GB file, file replaced mid-download, token revoked, low disk, Android Task Manager stop + dataSync timeout + standby buckets, notification permission denied, iOS `Authorization` header on a background task.

## Downloads screen (`(tabs)/downloads.tsx`, `show-downloads/[id].tsx`, `DownloadRow`, `StorageBar`)

- Active account only (`accountId === active.id`). Nothing → `Message`. Header: Delete All (trash, only with downloads) → `Alert` with count + size → `deleteDownloads` (running ones too; other accounts untouched).
- Storage bar (fixed under the title, outside the scrolling list): the account's downloads (sum of `total`) vs free space from `getFreeDiskStorageAsync` (purgeable included, like the pre-flight), re-read when a download is added, removed or finishes (not on tab focus or as bytes land). The store keeps its own `freeSpace()` (private, falls back to `Paths.availableDiskSpace`); the tab shows the text only, no bar, when the call fails.
- One list (decided 2026-10-10): newest first, running ones included (no Downloading / Ready sections). A movie (or video) = one row; a show = one row (`ShowDownloadRow`: name, "3 episodes · 1.8 GB", Downloading / Paused + a display-only ring over all its episodes while any isn't done, chevron) where its latest episode would be. Tap → `show-downloads/[id]` (params `id` = series id, `name` = the header title): its episodes by season (`Season n`, `Specials`, unnumbered last as `Episodes`), in episode order, rows titled "3. Pilot". It goes back by itself once its last episode is deleted.
- Search + type chips (fixed under the storage bar, shown with downloads): `SearchField` + All / Movies / Shows / Episodes `Chip`s narrow the list on the device (no server call, no debounce): `downloadList` builds the account's rows + folded search text once, `filterDownloads` keeps the same row objects per keystroke (rows keep their memo). A term matches a movie's title, or a show's name as its row shows it ("TV Show" too) or any of its episode titles (case and accents ignored); a matched show keeps its row with all episodes. Movies = every download without a show (videos too). Episodes = every episode on its own row, newest first, titled "Pioneer One · S1:E3 · Pilot" (`downloadList` `episodes`; the code alone without a season, none without numbers); a term matches that title. Reset to empty + All on an account switch. Storage bar, Delete All and its count stay over every download of the account. Nothing left → `Message` ("No downloads match "x"." / "No movies downloaded." / "No episodes downloaded.").
- The store keeps `seriesName`, `seasonNumber`, `episodeNumber` per episode (from the item at start). Episodes from before get them from their saved item JSON on load (or when the snapshot is retried); only without one do they show "TV Show" and no numbers. `downloadGroup(account, { seriesId })` = a show's summary (the row's ring).
- Rows: virtualised (tab `FlatList`, a show's screen `SectionList` with a section per season, headers not sticky) so 100+ shows stay smooth; the list re-renders on structure only (`useDownloadList`); each row reads its own `useDownload(id)` / `useDownloadSummary`. Poster = `snapshot.poster` (`snapshotUri`, `file://`; an episode's is its show's), placeholder until saved. List, seasons and status text are pure (`src/downloadList.ts`); status from `status` + `reason`: Waiting, Downloading, Waiting for Wi-Fi (`reason: network`, from the native `waiting` event; "Waiting for network" when the setting is Any network), Paused, Paused - sign in again (auth), Failed (- not enough space / - network / - downloads not allowed: native ends a 403 as error + auth). Ready rows and show rows are buttons; the others have the long-press "More" action. A running / paused row's ring opens the same menu as the long press.
- Ring (not done): tap opens the row menu (`DownloadMenu`, the `downloadActions` rules for one download, live on its own so progress doesn't re-render the screen; closes when the download goes). Ready row tap → `GET /Items/{id}` for the resume point → `openPlayer` (streams; the local file plays in M6). Lookup failed → from the start; dropped if the account changed meanwhile (`useDownloadActions`, shared by both screens).
- Delete: swipe a row left → red Delete (`SwipeToDelete`, Gesture Handler `ReanimatedSwipeable`; the screens wrap themselves in `GestureHandlerRootView`) - any row, running ones too; a show row deletes all its episodes. Long press (and the ring): a download → `ActionSheet` Pause / Resume Download + Cancel Download while not finished, "Delete Download" once done; a show → the delete confirm (VoiceOver can't swipe). All use `confirmDeleteDownloads` ("Delete the downloads of Pioneer One?" for several). Jest renders the swipe actions next to the row (`jest.setup.ts` mock).

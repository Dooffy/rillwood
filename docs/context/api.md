# API, auth + session

Read before working on `src/api.ts` (fetch client, endpoints, DTO types), `src/useFetch.ts` or `src/session.ts` / `src/auth.ts` (accounts, tokens, sign-in flows), or any server call. Rules here extend root `CLAUDE.md` §2 / §10. Per-version test results, curl examples: [`docs/research/jellyfin-api.md`](../research/jellyfin-api.md).

## Rules

- Plain `fetch` wrapper, hand-written DTO types, no `any` (root §2, §10). 8s fail-fast timeout, `ApiError`, offline flag; `/System/Info/Public` probe on foreground.
- Offline mode (`src/connection.ts`, `initConnection` from the root layout): `GET /System/Info/Public` on the active server (public, no auth; a normal request, so it sets / clears the offline flag) at launch (a background launch - an iOS download relaunch - waits until it's on screen), back from the background, back from a quick switch (Control Center, where airplane mode goes off) while offline, and when the active server changes (the old server's state is dropped at once - `resetOffline`; another account on the same server: no check). While offline it checks again after 5 s, 10 s, 20 s, then every 30 s - only on screen; the backoff starts over each time the app goes offline. Any request that answers clears the flag too (and drops the scheduled check). Signed out of the last account: the check and timer stop. Back online, `onReconnect` listeners run once the request that brought it back has settled: `useFetch` (`retryFailed`: mounted hooks whose last request failed for lack of a connection fetch again, not one still running; a 404 / 5xx / parse failure waits for Retry) and `usePagedItems` (a list with a `network` error retries). Read the flag with `isOffline()` / `useOffline()` (offline detail, Downloads row - `docs/context/downloads.md`); since this check they know at launch and on return, not only after a request failed. No NetInfo (root §2).
- Connection errors (UI): a `network` `ApiError` (no network, server down, timeout, TLS - `isConnectionError` in `api.ts`, also what `useFetch` / `usePagedItems` retry on reconnect) is told apart from an answer (5xx: "The server ran into a problem", other: "Couldn't load this"; 401 signs out). One offline state, `Offline`: a surface card (max 400 wide) - wifi-slash icon in a circle, "Can't reach <server name>", "Check your connection, or watch something you've downloaded.", Retry (filled, full width) and Go to Downloads (a link; `openDownloads`: closes what is over the tabs, switches to Downloads); always at the top (under a tab's title; under the floating header on detail and the player), alone on the screen with nothing to scroll. Home: Continue Watching + Next Up out of reach → the card; nothing else loaded → alone, else on top of what did (a cached Recently Added row). Held while a Retry (or the reconnect retry) runs - `useHeldOffline`, Retry busy - so the page behind doesn't flash in. Library then hides search, type chips, sort and filters unless there is something to undo (a search typed, another type, filters on). A failure inside a loaded page (a series' seasons / episodes) stays a small inline message + Retry. `LoadError` picks it for a connection error, else the copy for its kind + Retry. Shown where nothing loaded: Home (every top row out of reach), Library, a Library list's next page, item / series detail, the player for an item not downloaded. No banner: a page that loaded keeps its content, and a Home row out of reach is hidden (the rest stays), back by itself on reconnect. Offline detail of a downloaded item uses the saved copy instead (`docs/context/downloads.md`).
- `src/api.ts`: `request(conn, path, {method, query, body, signal, probe})`. `ServerConnection = {baseUrl}` for public endpoints (no auth header); `Connection` adds `deviceId`, then `token` + `accountId` once signed in. Errors are always `ApiError`: `network` (unreachable or no answer in 8s - sets the offline flag), `http` + `status`, `aborted` (caller cancelled - ignore), `parse`. Any server answer clears the offline flag; `probe` requests (address checks) never touch it. Error messages carry method + path only, never the query or token. A 401 on a call with an `accountId` fires `onUnauthorized(accountId, token)`; failed sign-ins don't. The session signs out only if that token is still the account's current one (a late 401 for a replaced token is ignored). `findServer` probes all address candidates in parallel, returns the first in order (https before http) that answers with `Id` + `Version`, and cancels the rest.
- Server target: **Jellyfin 12.1 base**, 12.0 + 10.11.x supported, warn below 10.10.7 (`isOutdatedServer` in `src/server.ts`, shown on Sign in).
- Server address (`serverUrlCandidates` in `src/server.ts`): trim, lowercase scheme + host, keep port and reverse-proxy sub-path, drop `/web/...`, query, hash and trailing `/`. No scheme → probe `https://` then `http://`. Reject `user:pass@`, other schemes, bad ports.
- Launch: signed in → Home; otherwise always Welcome (onboarding), also after sign out / last account removed / global 401 (`useSignedOutRedirect` in the root layout clears the stack to it). With saved signed-out accounts Welcome adds "Use a saved account" → Accounts (the same list as Settings) → Sign in (username prefilled). Welcome → Add server → Sign in run as onboarding (`onboarding=1`): step pills and explanations. Add server always shows "Where do I find it?" (from Add account too, without the steps); no example chips - the placeholder and the invalid-address error show the format. Sign in / Quick Connect success clears the stack to Home (`resetTo`).
- Accounts UI (`src/components/AccountList.tsx`, top of Settings + the signed-out Accounts page): one row per account (avatar, name, server; checkmark = active, "Sign in" = signed out). Tap: switch at once (no confirm) → toast "Switched to x" + stack cleared to the new account's Home; active row → its details; signed-out row → Sign in (username prefilled). (i) on every row → Account (`/account?id=`, default the active one): status, server details, Switch to this account / Sign in, Sign out (confirm when it has downloads), Remove account (confirm) - both delete the account's downloads. Add account: action sheet of saved servers (once each) + New server; nothing saved → Add server.
- Auth screens call `src/auth.ts`: `probeServer` (→ `findServer`), `signIn`, `quickConnectEnabled`, `quickConnect(server, {signal, onCode})` (initiate, poll every 5s, authenticate; aborting stops polling and adds no account), `authErrorMessage` (network / not Jellyfin / 401).
- Sign in / Quick Connect get only `url` (+ `userName` prefill) as route params and resolve it with `knownServer` - a server probed this run or saved with an account. Unknown url (e.g. a `rillwood://login?url=...` deep link) → back to Add server.
- **Auth header only.** 12.x rejects `X-Emby-Token`, `?api_key=` and the `Emby` scheme (10.11 still accepts them). `?ApiKey=` still works on both but is banned - no tokens in URLs.
  ```
  Authorization: MediaBrowser Client="Rillwood", Device="iPhone", DeviceId="<per-account id>", Version="0.1.0", Token="<token>"
  ```
- DeviceId: `expo-crypto.randomUUID()` minted for every sign-in (password or Quick Connect) and stored with the account, never shared between accounts (shared DeviceId clobbers sessions). It can't depend on the user id - sign-in already sends it. After sign-in, an existing account with the same `ServerId` + `User.Id` is replaced: `logout` its old token, keep one record.
- mpv sources: send `Authorization: MediaBrowser Token="<token>"` only. mpv joins headers into a comma-separated list, so the full header splits and Jellyfin returns 400 (`docs/test-plans/mpv.md` I1).
- Login and Quick Connect send the same header without `Token` (400 without `Device` / `DeviceId`).
- Server behaviour: same account + same DeviceId re-login revokes the older token; 10.11 merges sessions of different users on one DeviceId. The app never reuses a DeviceId, so it revokes a replaced token with an explicit `logout`.
- 401 = bad / missing / revoked token on every authed endpoint (both versions) → global signed-out state, keep downloads. 403 = `userId` of another user. `userId` query params are optional (taken from the token).
- Served **without auth** on 10.11 + 12.1 (I10): `/Videos/{id}/stream` (static and non-static), `/Items/{id}/Images/*`, subtitle streams. Detect revoked tokens from API 401s, not playback. `/Items/{id}/Download` does enforce auth.
- Session (`src/session.ts`, a `useSyncExternalStore` store - the 401 listener and auth flows change it outside React): records in kv-store `session.accounts`, tokens in `expo-secure-store` `tok_<accountId>` (read sync on boot; an account without its token boots signed out). `accountId = <ServerId>.<UserId>`; a sign-in whose `ServerId` differs from the probed server's `Id` is rejected (a hostile server can't claim another server's accounts). Switch without restart. Sign out = revoke (`logout`) + forget token, keep the record (`signedOut`); the Account screen deletes its downloads first (`docs/context/downloads.md`); signing out the active account activates the next signed-in one. Remove = sign out + drop the record; removing the active account activates the next signed-in one. 401 on a signed-in call → signed out, no logout call, no switch to another account.
- `useFetch(path, {query, ttl})` (`src/useFetch.ts`): GET as the active account through `request`. In-memory cache per account (`accountId` → `path|query`, query sorted, `undefined` dropped), so one account never sees another's data; entries of signed-out / removed accounts are dropped before the next fetch. Fresh entry (default TTL 5 min) → no request; stale / missing → fetch, older data stays on screen (`loading` true). Hooks on the same key share one request; unmount, account switch or a new path drops the hook's result, and the request is aborted when its last hook leaves. Returns `{data, error, loading, refresh}`; `error` is the `ApiError` (401 already signs out via `request`), older `data` is kept. `invalidate(pathPrefix?)` marks matching entries stale for every account and their mounted hooks refetch (failed hooks with nothing cached too) with a new request - a running one may predate a change, so it is not joined and its answer is dropped; `refresh()` does the same for one key (pull to refresh). Other keys are untouched - no restart, errors kept. Signed out or `path = null` → idle.
- Home data (`src/items.ts`, pure, type-only imports so `npm run check:home` loads it with plain Node): row requests as `Endpoint` (`{path, query}` for `useFetch`), limit 20. Next Up sends `enableResumable=false` (in-progress episodes are in Continue Watching). Recently Added only for `movies` / `tvshows` views; `recentlyAdded` turns 10.11 episodes (and seasons) into one Series card each (`SeriesPrimaryImageTag` as its poster, the episode's parent thumb / backdrop kept), order kept. `playback(item)`: progress + seconds left from `PlaybackPositionTicks` / `RunTimeTicks`, none when played. Images: poster (episodes → series poster), landscape (episode still → series thumb / backdrop; others thumb → backdrop → poster), hero backdrop. `imageUrl(baseUrl, ref, width, scale)` → `fillWidth = ceil(width × scale)` rounded up to an `IMAGE_WIDTHS` step (240-2880: one URL, one cache entry per size), `quality=90`, `tag=`, no token.
- Home screen (`src/app/(tabs)/home.tsx`) renders `homeLayout` (`src/items.ts`, pure): hero = first Continue Watching item, else first Next Up (left out of its row), placeholder while either may still bring one. Each row: placeholders while loading, error + Retry (its own `refresh`), hidden when empty. All three top requests failed → one error + Retry; everything loaded empty, Recently Added rows included (each row reports its count) → empty message. Pull to refresh / Retry all = `invalidate` on `homePaths`; the spinner stays until the top rows answered + 500 ms (iOS: ending a refresh mid-gesture leaves the spinner over the content). Images sized from the card widths (`POSTER_WIDTH`, `LANDSCAPE_WIDTH`, hero = window width) × `PixelRatio.get()`. Cards open via `openItem` (`src/navigation.ts`): series → `/series/[id]`, else `/item/[id]`.
- Detail (`src/app/item/[id].tsx`, movies + episodes; the screen renders `detailView(item)` from `src/detail.ts`): `GET /Items/{id}` (`itemDetail`), only for ids that pass `isItemId` (empty / all-zero ids load the root folder). 404 → "This item isn't available.", other errors → `Message` + Retry (`loadErrorMessage`, shared with Home). The item comes from `useItem(id)` (`src/useItem.ts`, shared with the series screen and the player): with a download of it (`savedItem`, read once per screen), any failure (404 too - the file still plays) shows the item saved with the download instead: its saved art, no logo, no More Like This, "Showing the details saved with the download." above the actions; known offline (`useOffline`) → at once, not after the 8 s timeout, and a server answer that lands replaces it; a `DetailPlaceholder` (hero, title, actions, overview lines) while it loads, never a bare spinner. Hero image requested at about 2.2x the screen width (16:9 art cover-cropped to 4:5). `detailFacts` (year, runtime, age rating, score, resolution by width - 4096x1744 is 4K -, HDR type (`DOVIInvalid` is not Dolby Vision), default audio channels) as chips; `mediaRows` = what plays by default from the first media source (default audio else the first, default subtitle else Off) + track counts + every track (`tracks`, subtitles start with Off), `Version (n)` row when there are several sources; a row with several tracks, or a default too long to fit (`trackRowExpands`, label + value over 24 chars, a low guess - opening a row that fits is harmless), opens in place on tap to list every track in full, default ticked (`MediaRow`; the label never wraps, the value truncates); `castAndCrew` = actors / guest stars in billing order, then directors and writers, at most 24 (`personRole`: character for cast, job for crew). Layout: 4:5 hero (backdrop cover-cropped, scrim to the page), logo (`ImageTags.Logo`) or text title over it with "Movie · genres" / "S1:E2 · Season"; overview over 150 chars clamped to 3 lines + More. Chips add "Ends at" (`formatEndsAt`, device clock), Dolby Atmos (audio `Profile` / title), SDH (`IsHearingImpaired`) else CC. Resume (saved position) + Play from Start when in progress, else Play; both open `/player` with `id` + `start` (playback in M4). Watched and favourite = round toggles next to Play (filled white when on, read as selected; the label says what a tap does: "Mark as unwatched", "Remove from favourites"; no separate "Watched" label - the filled ✓ says it). Download (header right) = `DownloadButton` (`docs/context/downloads.md` Download button). Episodes link to their series.
- Empty / error / loading states (M4S): one look - `Message` (secondary text + optional Retry; `fill` centres it on a whole screen, `alert` announces an error that appears in place). Exceptions, both the same card (`StateCard` in `Message.tsx`) at the top under the title: `Offline` (server out of reach) and `Empty` (a tab with nothing in it before first use - Downloads). Copy says what to do next: `loadErrorMessage` = offline "Couldn't reach the server. Check your connection and try again.", 5xx "The server ran into a problem. Try again in a moment.", else "Couldn't load this. Try again." (the player's `playErrorMessage` says the same for offline and 5xx - written out in `playback.ts`, which stays import-free for `check:home`; a test keeps them equal); empty texts name the next step (add media in Jellyfin then pull to refresh, check the spelling, clear a filter). Loading where the layout is known = grey placeholders (`Skeleton.tsx`: `CardRowPlaceholder` (also Home's shelves), `DetailPlaceholder`, `EpisodeCardsPlaceholder`, `EpisodeRowsPlaceholder`, `PosterGridPlaceholder`, `PosterRowsPlaceholder`), one "Loading" element for screen readers. Spinners only where the layout isn't known (player, footer of a paged list, Quick Connect code). Series: episode placeholders also while Next Up picks the season to open (not when that request never starts). Library rows (All / search) pull to refresh like the grid. Left as is: More Like This hides on error (extra content), genre list errors leave the filter without genres, the player has no load timeout (I15).
- Series data (`src/items.ts`, pure; screen in the next PR): `seasons` (`/Shows/{id}/Seasons`, Specials = index 0), `episodes` (`/Shows/{id}/Episodes?seasonId=&fields=Overview` - no overview by default), `seriesNextUp` (`/Shows/NextUp?seriesId=&limit=1&enableResumable=true`: in-progress episode, else the one after the highest watched, else S01E01 - same on 10.11 + 12.1; empty after the last episode), `similar` (`/Items/{id}/Similar?limit=20`, `{Items}`, often empty on sparse metadata). `nextEpisodes(episode)` (`/Shows/{seriesId}/Episodes?startItemId={id}&limit=2&isMissing=false`: the episode, then the next in series order - across seasons, no virtual missing episodes; only itself for the last; same on 10.11 + 12.1) + `nextEpisode(list, id)` for the player's Up Next (none when the next is `LocationType: Virtual` - `isMissing=false` may still let a not yet aired one through); movies have none. `defaultSeasonId` = season of the next episode, else the first real season; `seriesPlayTarget` = next episode (resume when started), else the first episode shown. `detailView` for series: "TV Show · genres", chips year range (`2019-2023`, `2019-` while continuing) + season count + rating + score; `directors` for "Directed by".
- Series screen offline (`useItem`): with episodes of it downloaded, a failure (or known offline) shows the show's saved name + poster, "Showing the details saved with the download." and a Downloaded Episodes button → `show-downloads/[id]`; no seasons, Next Up, cast or More Like This requests. Nothing downloaded → the error + Retry as before.
- Series screen (`src/app/series/[id].tsx`, Apple TV style): same hero / actions / overview / chips as the item detail (shared `DetailHero`, `DetailActions`, `Overview`, `CastRow`, `MoreLikeThis`). Season count from the season list (real seasons only, not `ChildCount`). "Play Episode" / "Resume Episode" (+ Play from Start) plays the next episode (else the first of the season shown), named underneath as "S2, E3 · Title: overview" (Next Up asks for `fields=Overview`); disabled until there is a target. The season opens once Next Up answers (or fails); several seasons → "Season n ⌃⌄" opens an `ActionSheet` ("Watched" / "n unwatched", checkmark on the current one), one season → a heading. Episodes: horizontal `EpisodeCard`s (one list per season, `key`), scrolled to the next episode but never past the last screenful: still, EPISODE n, title, 3 lines of overview (none reserved when no episode of the season has an overview), ▶ with a progress ring + time left / runtime / Watched, ♥ when a favourite, ⋯; card tap opens the episode detail, ⋯, long press and the VoiceOver actions (Play, More) open its actions; `ActionSheet` runs a picked action only after it has closed (iOS can't present the player modal while it is still up) - the shared item menu (`ItemMenu`, titled "S2, E3 · Name" here): Resume + Play from Start when started (else Play), Mark as Watched / Unwatched and Add to / Remove from Favourites following its state, Download / Pause / Resume / Delete Download by its state. Header ↓ = download the selected season (`DownloadButton`). The show's ✓ / ♥ mark the whole show / favourite it; the season menu ends with "Mark Season n as Watched / Unwatched" (one season: the heading has no menu, the show's ✓ covers it). Item detail adds "Directed by" and More Like This (hidden while loading, empty or failed).
- Item menu (`src/components/ItemMenu.tsx`): a long press on any card or row (Home hero + rows, Library rows / grid / episode list, More Like This, series episodes; VoiceOver: the card's "More" action) opens one shared `ActionSheet`, mounted once in the root layout (`ItemMenuProvider`, inside `ToastProvider`). Actions (`itemActions`): movies / episodes / videos get Resume + Play from Start when started (else Play); every item Mark as Watched / Unwatched (unwatching a show or season asks first - `useUserFlag`) and Add to / Remove from Favourites; movies / episodes / seasons Download / Pause Download / Resume Download / Delete Download by the download state (`downloadAction`; hidden when the user may not download); shows none (a show downloads a season at a time, from its screen). Shows and seasons have no Play - their detail picks the episode. Titled like the card ("Show · S1:E2 · Pilot"). Opening it dismisses the keyboard (Library search); it closes when the active account changes (switch, sign-out); a long press on a search result saves the search like a tap. `useItemMenu` throws outside the provider.
- Library (`src/app/(tabs)/library.tsx`, browse + search in one tab; there is no Search tab): one request builder, `listItems({term, scope, sort, filters}, limit, startIndex)` = `/Items` for every item of the type the user can see across libraries (no `parentId`), `recursive=true`. Types (capsules All / Movies / Shows / Episodes, default All): All searches `Movie,Series,Episode` in one request; one type uses its own type. With a term the server ranks the matches (no sort sent; it matches words starting with the term - "s" finds Sintel, Subs, Show; one mixed list, episodes can come before their show); without one the sort applies: Name (`SortName` asc), Date Added (`DateCreated` for movies, `DateLastContentAdded` for shows, desc), Year (`ProductionYear`), Rating (`CommunityRating`), each tied by `SortName` so pages stay stable - same on 10.11 + 12.1; unknown keys are ignored by the server, so they are fixed here. `searchTerm` searches from the first letter (trimmed, nothing for blanks); typing is debounced 300 ms (`useDebounced`).
- Library layout: one type = an endless `PagedList` (`usePagedItems` + `listItems(..., 50, startIndex)`): Movies / Shows as a 3-column poster grid, Episodes as a vertical `EpisodeRow` list, a count line ("11 movies · by Name", no sort part while searching), footer spinner, later-page errors in the footer with Retry (items stay), first-page placeholders / error + Retry / empty text, pull to refresh (`usePullToRefresh`, shared with Home). All = one row per type, each heading "See All ›" selects that type: one request per type (`ROW_LIMIT` 20, filtered; sorted while browsing, server-ranked while searching), so no type crowds out another (a broad term like "s" could fill one mixed request with episodes); Movies + Shows while browsing, + Episodes while searching. A new term / type / sort / filter starts a new list at the top; the list key is the request itself, so the sort (ignored while searching) doesn't restart it. The search key saves what is typed (not the debounced term). Header: round sort `MenuButton` and `FilterButton`; under the field the type capsules and the active filter tags. Recent searches (`src/recentSearches.ts`, per account, newest first, max 8, in memory for the session; added when a result is opened or the search is submitted) show while the empty field is focused, with Clear Recent. Empty texts: "No results for "x"." (+ "with these filters"), "Nothing matches these filters.", "No movies on the server yet."
- Paging (`src/usePagedItems.ts`): `usePagedItems(id, pageAt)`: first page on mount, `loadMore` (no-op while loading, at the end, or while an error shows - the list end re-fires on footer resize), `retry` repeats what failed (a failed pull to refresh refreshes again, a failed page loads it again), `refresh` (from page one, items kept until it answers), one request at a time (a new one aborts the last), reset per account + list id, `id = null` = idle. Pages advance by server offset (`mergePage` drops repeats without shifting it); an empty page ends the list whatever the total says; signed out = idle. Not tied to `invalidate()`: lists refresh on pull to refresh or a new query. Cards are memoised and `renderItem` / `useImage` are stable, so new pages don't redraw every card.
- Mark watched / favourite (`src/userData.ts`; buttons and menus call `useUserFlag`, which toasts `userFlagError` on failure - "Couldn't mark as watched. Check your connection and try again." - and asks first (`Alert`, destructive "Mark Unwatched") before unwatching a whole season or show, since that clears every episode's progress): `setPlayed` / `setFavourite` (`src/api.ts`) = `POST` (on) / `DELETE` (off) `/UserPlayedItems/{id}` / `/UserFavoriteItems/{id}`, answering the item's new UserData - same on 10.11 + 12.1. Watched or unwatched clears the resume point; a season / series marks every episode in it. Unknown id: 404 on 12.x, 500 on 10.11. `setUserFlag(item, 'played' | 'favourite', value)` is optimistic: `changedUserData` predicts the answer and `patchResponse` applies it to every cached `useFetch` response (`updateCached`; an item, a list, or `{Items}` - a season / series also marks its episodes) and to loaded paged lists (`onCacheUpdate`, fed by `updateCached`), so every screen shows it at once; the server's answer replaces it, then `invalidate()` refetches everything (Next Up, Continue Watching, counts). Failure → every changed item gets its own old UserData back (episodes of a season too), refetch, the `ApiError` is returned for a toast. A page that was loading during a change gets it applied when it lands. A quick second tap wins over the first one's late answer (latest call per account + item + flag). Signed out → 401 error, no request. Offline marks are not queued (offline playback progress is: `docs/context/sync.md`).
  `src/items.ts` + `FilterSheet` / `FilterChips` / `FilterButton`, in the Library): `Filters = {show, genres, decades, minRating, only4K}`; `filterQuery` → `/Items` params, same on 10.11 + 12.1: show → `filters=IsUnplayed | IsResumable | IsPlayed | IsFavorite`, genres → `genres=A|B` (any), decades → `years=2010,...,2019` (Older = 1900-1989), rating → `minCommunityRating`, 4K → `is4K=true`. No HDR / Dolby Vision filter: the server ignores `hasHdr`, `isHdr` and `videoRangeTypes`. Genre list: `/Genres?includeItemTypes=Movie,Series&recursive=true` (10.11 reports `TotalRecordCount` 0 - read `Items`). The sheet edits a draft, Reset clears it, its button shows a live count (`limit=0` request with the draft) and applies. Active filters show as small outlined tags with ✕ (`activeFilters` / `removeFilter`) + Clear; the round filter button fills with a count badge.

# API, auth + session

Read before working on `src/api.ts` (fetch client, endpoints, DTO types), `src/useFetch.ts` or `src/session.ts` / `src/auth.ts` (accounts, tokens, sign-in flows), or any server call. Rules here extend root `CLAUDE.md` §2 / §10. Per-version test results, curl examples: [`docs/research/jellyfin-api.md`](../research/jellyfin-api.md).

## Rules

- Plain `fetch` wrapper, hand-written DTO types, no `any` (root §2, §10). 8s fail-fast timeout, `ApiError`, offline flag; `/System/Info/Public` probe on foreground.
- `src/api.ts`: `request(conn, path, {method, query, body, signal, probe})`. `ServerConnection = {baseUrl}` for public endpoints (no auth header); `Connection` adds `deviceId`, then `token` + `accountId` once signed in. Errors are always `ApiError`: `network` (unreachable or no answer in 8s - sets the offline flag), `http` + `status`, `aborted` (caller cancelled - ignore), `parse`. Any server answer clears the offline flag; `probe` requests (address checks) never touch it. Error messages carry method + path only, never the query or token. A 401 on a call with an `accountId` fires `onUnauthorized(accountId, token)`; failed sign-ins don't. The session signs out only if that token is still the account's current one (a late 401 for a replaced token is ignored). `findServer` probes all address candidates in parallel, returns the first in order (https before http) that answers with `Id` + `Version`, and cancels the rest.
- Server target: **Jellyfin 12.1 base**, 12.0 + 10.11.x supported, warn below 10.10.7 (`isOutdatedServer` in `src/server.ts`, shown on Sign in).
- Server address (`serverUrlCandidates` in `src/server.ts`): trim, lowercase scheme + host, keep port and reverse-proxy sub-path, drop `/web/...`, query, hash and trailing `/`. No scheme → probe `https://` then `http://`. Reject `user:pass@`, other schemes, bad ports.
- Launch: signed in → Home; otherwise always Welcome (onboarding), also after sign out / last account removed / global 401 (`useSignedOutRedirect` in the root layout clears the stack to it). With saved signed-out accounts Welcome adds "Use a saved account" → Accounts → Sign in (username prefilled). Welcome → Add server → Sign in run as onboarding (`onboarding=1`): step pills and explanations. Add server always shows example addresses and "Where do I find it?" (from Accounts too, without the steps). Sign in / Quick Connect success clears the stack to Home (`resetTo`).
- Auth screens call `src/auth.ts`: `probeServer` (→ `findServer`), `signIn`, `quickConnectEnabled`, `quickConnect(server, {signal, onCode})` (initiate, poll every 5s, authenticate; aborting stops polling and adds no account), `authErrorMessage` (network / not Jellyfin / 401).
- Sign in / Quick Connect get only `url` (+ `userName` prefill) as route params and resolve it with `knownServer` - a server probed this run or saved with an account. Unknown url (e.g. a `rillwood://login?url=...` deep link) → back to Add server.
- **Auth header only.** 12.x rejects `X-Emby-Token`, `?api_key=` and the `Emby` scheme (10.11 still accepts them). `?ApiKey=` still works on both but is banned - no tokens in URLs.
  ```
  Authorization: MediaBrowser Client="Rillwood", Device="iPhone", DeviceId="<per-account id>", Version="0.1.0", Token="<token>"
  ```
- DeviceId: `expo-crypto.randomUUID()` minted for every sign-in (password or Quick Connect) and stored with the account, never shared between accounts (shared DeviceId clobbers sessions). It can't depend on the user id - sign-in already sends it. After sign-in, an existing account with the same `ServerId` + `User.Id` is replaced: `logout` its old token, keep one record.
- mpv sources: send `Authorization: MediaBrowser Token="<token>"` only. mpv joins headers into a comma-separated list, so the full header splits and Jellyfin returns 400 (`docs/test-plans/mpv.md` I1).
- Login and Quick Connect send the same header without `Token` (400 without `Device` / `DeviceId`).
- Server behaviour: same account + same DeviceId re-login revokes the older token; 10.11 merges sessions of different users on one DeviceId. The app never reuses a DeviceId, so it revokes a replaced token with an explicit `logout`.
- 401 = bad / missing / revoked token on every authed endpoint (both versions) → global signed-out state, keep downloads. 403 = `userId` of another user. `userId` query params are optional (taken from the token).
- Served **without auth** on 10.11 + 12.1 (I10): `/Videos/{id}/stream` (static and non-static), `/Items/{id}/Images/*`, subtitle streams. Detect revoked tokens from API 401s, not playback. `/Items/{id}/Download` does enforce auth.
- Session (`src/session.ts`, a `useSyncExternalStore` store - the 401 listener and auth flows change it outside React): records in kv-store `session.accounts`, tokens in `expo-secure-store` `tok_<accountId>` (read sync on boot; an account without its token boots signed out). `accountId = <ServerId>.<UserId>`; a sign-in whose `ServerId` differs from the probed server's `Id` is rejected (a hostile server can't claim another server's accounts). Switch without restart. Sign out = revoke (`logout`) + forget token, keep the record and its downloads (`signedOut`). Remove = sign out + drop the record; removing the active account activates the next signed-in one. 401 on a signed-in call → signed out, no logout call.
- `useFetch`: cache key `accountId|path`, TTL, abort, `invalidate()`.

## Endpoints (≈12)

| Feature            | Endpoint                                                                                                                                                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Validate / probe   | `GET /System/Info/Public`                                                                                                                                                                                                                             |
| Public users       | `GET /Users/Public` - empty when users are hidden (common); always allow manual username                                                                                                                                                              |
| Login              | `POST /Users/AuthenticateByName` `{Username, Pw}`                                                                                                                                                                                                     |
| Quick Connect      | `GET /QuickConnect/Enabled` → `POST /QuickConnect/Initiate` (GET is 405 on 12.x) → poll `GET /QuickConnect/Connect?secret=` → `POST /Users/AuthenticateWithQuickConnect {Secret}`. Tests approve headlessly with `POST /QuickConnect/Authorize?code=` |
| Logout             | `POST /Sessions/Logout`                                                                                                                                                                                                                               |
| Libraries          | `GET /UserViews?userId=`                                                                                                                                                                                                                              |
| Home rows          | `GET /UserItems/Resume?mediaTypes=Video` (12.1 adds Season / Series rows otherwise), `GET /Shows/NextUp`, `GET /Items/Latest?parentId=` (**bare array**; TV returns Series on 12.1, Episode on 10.11)                                                 |
| Grid               | `GET /Items?userId&parentId&includeItemTypes=Movie,Series&recursive=true&sortBy=&sortOrder=&filters=IsUnplayed&startIndex=&limit=50&fields=Overview,PrimaryImageAspectRatio` (unknown `sortBy` is silently ignored)                                   |
| Search             | `GET /Items?searchTerm=&includeItemTypes=Movie,Series,Episode&recursive=true`                                                                                                                                                                         |
| Detail             | `GET /Items/{id}?userId=` - never with an empty / zero id (returns the root folder)                                                                                                                                                                   |
| Seasons / episodes | `GET /Shows/{id}/Seasons`, `GET /Shows/{id}/Episodes?seasonId=`                                                                                                                                                                                       |
| Playback info      | `POST /Items/{id}/PlaybackInfo` with DeviceProfile `MaxStreamingBitrate` (400 Mbps) + `DirectPlayProfiles:[{Type:"Video"}]` + subtitle profiles **Embed and External**. Check `SupportsDirectPlay` (false comes with no error code)                   |
| Stream             | `GET /Videos/{id}/stream?static=true&mediaSourceId=` (auth header)                                                                                                                                                                                    |
| External subs      | `GET /Videos/{id}/{msId}/Subtitles/{index}/Stream.{srt/ass/vtt}` - build it in the client, never use the server `DeliveryUrl` (contains `ApiKey=<token>`)                                                                                             |
| Reporting          | `POST /Sessions/Playing`, `/Sessions/Playing/Progress` (10s + pause/seek), `/Sessions/Playing/Stopped`                                                                                                                                                |
| Download           | `GET /Items/{id}/Download` (original file; Range + `If-Range: <Last-Modified>` supported, no ETag, **HEAD is 405**)                                                                                                                                   |
| Played             | `POST /UserPlayedItems/{id}?datePlayed=` / `DELETE`                                                                                                                                                                                                   |
| User data          | `GET` / `POST /UserItems/{id}/UserData` `{PlaybackPositionTicks, LastPlayedDate, Played}` - offline sync (`docs/context/sync.md`)                                                                                                                     |
| Images             | `GET /Items/{id}/Images/{type}?fillWidth=&quality=90&tag=` (`tag=` gives 1-year cache headers; 404 when the type is missing - fallback UI)                                                                                                            |

Ticks: 10,000,000 per second. Server resume rules (defaults, both versions): position < 5% → 0, ≥ 90% → Played, items < 300s get no resume point.

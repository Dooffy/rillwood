# Local Jellyfin for development

Pinned Jellyfin servers in Docker plus a generated test library, so every contributor tests against the same thing.

| Server          | Port   | Start                                   |
| --------------- | ------ | --------------------------------------- |
| **12.1** (base) | `8096` | `docker compose up -d`                  |
| 10.11 (compat)  | `8097` | `docker compose --profile compat up -d` |

## First run

```bash
cd dev/jellyfin
./make-test-media.sh             # ~10 min, ~700 MB into ~/rillwood-media (needs ffmpeg + node)
docker compose up -d
node setup.mjs                   # wizard, users, libraries, showcase; safe to re-run
node setup.mjs --server http://localhost:8097   # compat server, if started
```

Open http://localhost:8096 to check. **Dev-only** logins - never reuse them on a real server:

| User    | Password         | Sees                                                               |
| ------- | ---------------- | ------------------------------------------------------------------ |
| `admin` | `admin-rillwood` | everything                                                         |
| `test`  | `test-rillwood`  | test media: Movies, Shows, Real                                    |
| `demo`  | `demo-rillwood`  | showcase: Films, TV Shows, with watch history (screenshots, demos) |

## Media

Set `RILLWOOD_MEDIA` to use another folder (default `~/rillwood-media`). It's mounted read-only at `/media` and never committed.

| Folder    | Library | Contents                                                                                                                                                                                                                                                                                                                                                                        |
| --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `movies/` | Movies  | Generated: H.264 / HEVC 10-bit / HDR10 / AV1 / 4K HEVC; AAC, AC3, E-AC3, DTS, TrueHD; SRT + ASS; multi-audio + multi-subs; sidecar SRTs (`Sidecar Subs`, `Missing Sidecar` - delete its `.de.srt` after the scan for B13, `docs/test-plans/mpv.md`); Japanese, Chinese, Korean, Arabic, Hebrew subs; 7-min `Resume Test` (Jellyfin keeps resume points only for items >= 5 min) |
| `shows/`  | Shows   | Generated: `Test Show` S01E01-03, 2 min each (Next Up, autoplay next; too short for server resume points); `Language Show` S01E01-03, 30 s, English + Ukrainian audio and subtitles - E02 lists Ukrainian first (B16); `Long Show` S01-S02 x 25 episodes, 30 s, ~4 MB each (long Downloads lists, L8)                                                                           |
| `real/`   | Real    | **Not generated by the script.** Recipes in [`docs/research/real-test-media.md`](../../docs/research/real-test-media.md) (helpers in `real-media/`): `Sintel (2010)` 4K 11 min (CC-BY, ~3.8 GB download) for B6, and a DV P8.1 + TrueHD + PGS clip built from it for C4. Optional by hand: a real HEVC 10-bit remux, a real DV grade                                            |

## Showcase library (store screenshots)

Fake movies and shows with real-looking artwork, for screenshots that show no real films or test patterns. Built by the first-run steps above; sign in as `demo`. On their own:

```bash
node make-showcase-media.mjs     # ~400 MB into ~/rillwood-media/showcase (make-test-media.sh runs it)
node showcase.mjs                # libraries, demo user, scan, NFO re-read, watch state (setup.mjs runs it); ~10 s
```

Re-run `node showcase.mjs` before a screenshot session - it puts demo's watch state back.

**Download screenshots** (on request - `/showcase large` in Claude Code, or by hand): the normal files are ~20 MB, so Downloads would show tiny sizes. `--large-files` pads the titles with `downloadGB` in `showcase.json` (Glass Orbit, Velvet Hours, The Brass Detective, Frostmark, Wild Atlas - ~16 GB) with Matroska filler; playback doesn't change. Sparse on the Mac, real bytes on the device once downloaded.

```bash
node make-showcase-media.mjs --large-files && node showcase.mjs   # then download them in the app as demo
node make-showcase-media.mjs --small-files && node showcase.mjs   # back to normal (delete the downloads in the app too)
```

| What                                                                                 | Where                                                               |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Titles, overviews, ratings, runtimes, episodes, demo watch state                     | `showcase/showcase.json`                                            |
| Fictional cast (with roles), directors, writers, studios - the detail hero's credits | `showcase/showcase.json` (all names invented: `showcase/README.md`) |
| Artwork: `poster.jpg` (2:3), `backdrop.jpg` (16:9), `S01E0N.jpg` episode stills      | `showcase/art/<slug>/`                                              |

- 10 movies + 5 shows x 6 episodes. Each video is its backdrop / still looped at the full runtime (1 fps, silent 5.1 audio, an English subtitle track that's off), so runtimes, time left and progress bars look real.
- Libraries `Films` / `TV Shows` (Home says "Recently Added in Films"; `Movies` / `Shows` are taken by the test libraries) read only the NFOs and artwork next to the files (no online lookups - the fake titles would match real films). `demo` sees only them; `test` sees everything else.
- Demo state: 2 movies + some episodes watched (Next Up: Driftline, Frostmark, The Orchard House), 3 in progress (Continue Watching: Glass Orbit first), 3 favourites. Change it in `showcase.json` `demo`.
- New title: add it to `showcase.json` + its artwork under `showcase/art/<slug>/`, then run both scripts again. Changed runtime or artwork: delete that title's `.mkv` in `$RILLWOOD_MEDIA/showcase` first (existing videos are skipped).

## Phone access

By default the servers listen on **localhost only** (simulator and browser work). The dev logins are public (in this README), so only open them to the LAN on a **trusted** network (home, not cafe/coworking):

```bash
RILLWOOD_BIND=0.0.0.0 docker compose up -d   # LAN access while you test on the phone
ipconfig getifaddr en0                       # e.g. 192.168.1.20 -> http://192.168.1.20:8096
docker compose up -d                         # back to localhost-only afterwards
```

iOS asks for **Local Network** permission the first time the app connects - allow it.

## Reset / stop

```bash
docker compose down              # stop (state kept in data/)
rm -rf data && mkdir -p data/12/config data/12/cache && docker compose up -d && node setup.mjs   # fresh server
```

Version bumps: change the pinned image tags in `compose.yml` and note it in `CLAUDE.md` §2.
